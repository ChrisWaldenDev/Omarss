# Decisions

Record any choice the spec doesn't settle, and any proposed change to the spec.
One line each, newest at the bottom: `YYYY-MM-DD: decision (reason)`.

- 2026-09-27: Database stays embedded SQLite (single file in the data dir, no server or Docker) (spec §3/§5; owner confirmed).
- 2026-09-27: Project renamed from Rill to omarss; app identifier `dev.omarss.app` (owner decision).
- 2026-09-27: Package manager is npm with a committed `package-lock.json` (only one available in the dev environment; simplest for CI).
- 2026-09-27: TypeScript is pinned to `~6.0` (svelte-check and typescript-eslint don't support TypeScript 7 yet).
- 2026-09-27: tauri-specta `=2.0.0-rc.25` / specta `=2.0.0-rc.25` are pinned exactly (pre-release crates; upstream asks for `=` pins).
- 2026-09-27: The generated IPC file is `src/lib/types.ts`, holding both the types and the typed command wrappers (tauri-specta emits them as one file; §4.2 names `types.ts` as the generated file). `src/lib/api.ts` turns each command's `Result` into a thrown `ApiError { kind, message }`.
- 2026-09-27: Bindings are regenerated by `cargo test` (`export_typescript_bindings`, also `npm run gen:bindings`) and on every debug launch, writing only when the content changed. CI fails if `src/lib/types.ts` is stale (keeps hand edits and drift out).
- 2026-09-27: Rust `i64` IDs and timestamps are exported to TypeScript as `number` (`dangerously_cast_bigints_to_number`) (SQLite rowids and Unix seconds stay far below 2^53).
- 2026-09-27: Storage paths use Tauri's base dirs (`config_dir`, `local_data_dir`) plus an `omarss` sub-directory, not the identifier-based `app_*_dir` helpers (those would give `dev.omarss.app/` instead of the `omarss/` paths in §11.1). DB is `<data>/omarss.sqlite`.
- 2026-09-27: Logs go to `<data>/logs/` on both OSes, rotated daily, 7 kept; default filter `warn,omarss_lib=info`, overridable with `RUST_LOG` (§11.1 allows the data dir on Linux; one location is simpler).
- 2026-09-27: Pre-migration backups are named `pre-migration-<N>.sqlite`, where N is the first version about to be applied, and are written with `VACUUM INTO` (consistent copy of a WAL database). Only taken when the DB already has a schema.
- 2026-09-27: Migrations run on a dedicated connection with foreign keys off (so later migrations can rebuild tables), followed by `PRAGMA foreign_key_check`. Pooled connections (r2d2, 8) use `foreign_keys=ON`, `synchronous=NORMAL`, `busy_timeout=5000`.
- 2026-09-27: A database whose schema version is newer than the app supports is refused with an error instead of opened (avoids silently corrupting data after a downgrade).
- 2026-09-27: Migration 0001 inserts the Local account (§9.1: there is always exactly one Local account).
- 2026-09-27: Settings are stored one row per `Settings` field (key = camelCase field name, value = JSON). Missing, unknown or invalid rows fall back to that field's default. `update_settings` saves the whole object. M1 has one setting, `theme` (default `system`).
- 2026-09-27: Theme is applied as `data-theme` on `<html>`; "System" removes it and CSS `prefers-color-scheme` decides. The backend also sets the native window theme so the title bar matches.
- 2026-09-27: M1 dummy data comes from `src-tauri/src/demo.rs`, served through the real read commands (`get_sidebar`, `list_articles`, `get_article`) and never written to the DB. M2 replaces it with store repositories, keeping the frontend unchanged.
- 2026-09-27: The unread-only list filter doesn't apply to the Starred view (starred articles would otherwise disappear from Starred once read); the toggle is hidden in the Starred and Unread views.
- 2026-09-27: App CSP is §11.4's policy plus `connect-src ipc: http://ipc.localhost` (Tauri 2's IPC transport; Tauri's docs require it). `devCsp` also allows the Vite HMR socket. The Windows form of the image protocol (`http://omarss-img.localhost`) will be added in M3 with the protocol itself.
- 2026-09-27: The WebView capability grants no plugin permissions. Links are opened by the `open_external` command (http/https/mailto only) through the opener plugin's Rust API, and a navigation-guard plugin cancels any WebView navigation away from the app (§8.2, §11.4).
- 2026-09-27: Frontend state lives in Svelte 5 rune classes in `src/lib/stores/*.svelte.ts`; UI strings are in `src/lib/i18n/en.json` via `t(key, params)` (§12 i18n).
- 2026-09-27: The article list isn't virtualised in M1 (demo data is under 50 rows); virtualisation lands with the real list in M2 (§6.2).
- 2026-09-27: `.gitattributes` forces LF line endings so Prettier checks and generated bindings match on Windows. CI runs frontend lint/format/type checks once on Linux, and Rust fmt/clippy/tests plus the app build on both Ubuntu 22.04 and Windows.
- 2026-09-27: PROPOSAL (needs owner decision before FTS writes land in M2/M4): §5's `articles_fts` is contentless (`content=''`), so rows can't be deleted without their original text, and `ON DELETE CASCADE` from feeds bypasses Rust entirely. Proposed fix: add `contentless_delete=1` (SQLite ≥ 3.43, bundled) and an `AFTER DELETE ON articles` trigger that deletes the matching FTS row. M1 creates the table exactly as specified.
- 2026-09-27: Every merge to main publishes a GitHub Release with Linux (`.AppImage`, `.deb`, `.rpm`, built on Ubuntu 22.04) and Windows (NSIS `-setup.exe`, `.msi`) installers, once CI passes on that commit (`.github/workflows/release.yml`) (owner decision; replaces §13's "build bundles on tags"). Pull requests that change packaging run the same builds without publishing.
- 2026-09-27: Release version = `<major>.<minor>` from `src-tauri/tauri.conf.json` + `.<number of commits on main>` (e.g. `0.1.7`, tag `v0.1.7`); the repo's patch digit is ignored. To start 0.2, bump the version in `tauri.conf.json`, `Cargo.toml` and `package.json` (owner chose numbered per-merge builds; purely numeric versions because RPM forbids `-` in versions, and deb/rpm would sort `0.1.0-N` after `0.1.0`, unlike semver; always increasing because main can't be force-pushed).
- 2026-09-27: Windows installers are not code-signed until a certificate exists (SmartScreen warns on first run). Updater signing stays in M8.
- 2026-09-27: Windows installers embed the WebView2 bootstrapper (§2: "WebView2 bootstrapper included").
- 2026-09-27: On MSVC targets, the Common Controls v6 manifest is embedded through the linker (`/MANIFEST:EMBED`) instead of by tauri-build (which only covers binaries), so `cargo test` executables start on Windows instead of failing with `STATUS_ENTRYPOINT_NOT_FOUND`.
- 2026-09-27: FLAG for M8 (spec conflict): the AppImage is about 100 MB because it bundles WebKitGTK, far above §12's "< 25 MB AppImage" target; the `.deb`/`.rpm` are about 5 MB. The target likely needs revising, or the AppImage dropping, when packaging is finalised.
- 2026-09-27: Pull requests that only change documentation (Markdown files anywhere, `docs/`, `LICENSE`) skip CI's slow app jobs (Rust fmt/clippy/tests and app builds on Linux and Windows); the frontend job still runs. The skip is done at job level, so skipped jobs report "skipped" and would still satisfy required checks. Pushes to main always run everything, because they gate releases and fill the build caches (owner request).
- 2026-09-27: The display name is **Omarss**: product name, window title, UI, installer and release names, publisher, and docs. This matches the other oma apps (Omacalc, Omacut, Omawrite), which use a Title-case `Name=` and lowercase technical names. Technical identifiers therefore stay lowercase `omarss`: binary, desktop file, icon, window class, deb/rpm package, npm package (npm requires lowercase), Cargo crate, identifier `dev.omarss.app`, data/config folders (existing installs keep their data), `omarss-img://`, `.omarssbackup`, keyring key, and the repo name (owner request).
- 2026-09-27: The Windows MSI upgrade code is pinned to `586b92e7-c31b-5a7b-8797-17cbcbb6f245`, the value Tauri derived from the old product name "omarss". Tauri derives the code from `productName` case-sensitively, so without the pin, installs from v0.1.5 and earlier would sit alongside new ones instead of upgrading.
- 2026-09-27: The Linux desktop file is named `Omarss.desktop`. Tauri 2 always names it after `productName`, and this cannot be configured, so it differs from the siblings' lowercase file names. It still sets `Exec`, `Icon` and `StartupWMClass` to `omarss`, and the window class is `omarss`, so desktops still match windows to the launcher entry.
