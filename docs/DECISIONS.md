# Decisions

Record any choice the spec doesn't settle, and any proposed change to the spec.
One line each, newest at the bottom: `YYYY-MM-DD: decision (reason)`.

- 2026-09-27: Database stays embedded SQLite (single file in the data dir, no server or Docker) (spec §3/§5; owner confirmed).
- 2026-09-27: Project renamed from Rill to omarss; app identifier `dev.omarss.app` (owner decision).
- 2026-09-27: Package manager is npm with a committed `package-lock.json` (only one available in the dev environment; simplest for CI).
- 2026-09-27: TypeScript is pinned to `~6.0` (svelte-check and typescript-eslint don't support TypeScript 7 yet).
- 2026-09-27: tauri-specta `=2.0.0-rc.25` / specta `=2.0.0-rc.25` are pinned exactly (pre-release crates; upstream asks for `=` pins).
- 2026-09-27: The generated IPC file is `src/lib/types.ts`, holding both the types and the typed command wrappers (tauri-specta emits them as one file; §4.2 names `types.ts` as the generated file). `src/lib/api.ts` turns each command's `Result` into a thrown `ApiError { kind, message }`.
- 2026-09-27: Bindings are regenerated by `cargo test` (`export_typescript_bindings`, also `npm run gen:bindings`) and on every debug launch, writing only when the content changed. CI fails if `src/lib/types.ts` is stale (keeps hand edits and drift out).
- 2026-09-27: Rust `i64` IDs and timestamps are exported to TypeScript as `number` (`dangerously_cast_bigints_to_number`) (SQLite rowids and Unix seconds stay far below 2^53).
- 2026-09-27: Storage paths use Tauri's base dirs (`config_dir`, `local_data_dir`) plus an `omarss` sub-directory, not the identifier-based `app_*_dir` helpers (those would give `dev.omarss.app/` instead of the `omarss/` paths in §11.1). DB is `<data>/omarss.sqlite`.
- 2026-09-27: Logs go to `<data>/logs/` on both OSes, rotated daily, 7 kept; default filter `warn,omarss_lib=info`, overridable with `RUST_LOG` (§11.1 allows the data dir on Linux; one location is simpler).
- 2026-09-27: Pre-migration backups are named `pre-migration-<N>.sqlite`, where N is the first version about to be applied, and are written with `VACUUM INTO` (consistent copy of a WAL database). Only taken when the DB already has a schema.
- 2026-09-27: Migrations run on a dedicated connection with foreign keys off (so later migrations can rebuild tables), followed by `PRAGMA foreign_key_check`. Pooled connections (r2d2, 8) use `foreign_keys=ON`, `synchronous=NORMAL`, `busy_timeout=5000`.
- 2026-09-27: A database whose schema version is newer than the app supports is refused with an error instead of opened (avoids silently corrupting data after a downgrade).
- 2026-09-27: Migration 0001 inserts the Local account (§9.1: there is always exactly one Local account).
- 2026-09-27: Settings are stored one row per `Settings` field (key = camelCase field name, value = JSON). Missing, unknown or invalid rows fall back to that field's default. `update_settings` saves the whole object. M1 has one setting, `theme` (default `system`).
- 2026-09-27: Theme is applied as `data-theme` on `<html>`; "System" removes it and CSS `prefers-color-scheme` decides. The backend also sets the native window theme so the title bar matches.
- 2026-09-27: M1 dummy data comes from `src-tauri/src/demo.rs`, served through the real read commands (`get_sidebar`, `list_articles`, `get_article`) and never written to the DB. M2 replaces it with store repositories, keeping the frontend unchanged.
- 2026-09-27: The unread-only list filter doesn't apply to the Starred view (starred articles would otherwise disappear from Starred once read); the toggle is hidden in the Starred and Unread views.
- 2026-09-27: App CSP is §11.4's policy plus `connect-src ipc: http://ipc.localhost` (Tauri 2's IPC transport; Tauri's docs require it). `devCsp` also allows the Vite HMR socket. The Windows form of the image protocol (`http://omarss-img.localhost`) will be added in M3 with the protocol itself.
- 2026-09-27: The WebView capability grants no plugin permissions. Links are opened by the `open_external` command (http/https/mailto only) through the opener plugin's Rust API, and a navigation-guard plugin cancels any WebView navigation away from the app (§8.2, §11.4).
- 2026-09-27: Frontend state lives in Svelte 5 rune classes in `src/lib/stores/*.svelte.ts`; UI strings are in `src/lib/i18n/en.json` via `t(key, params)` (§12 i18n).
- 2026-09-27: The article list isn't virtualised in M1 (demo data is under 50 rows); virtualisation lands with the real list in M2 (§6.2).
- 2026-09-27: `.gitattributes` forces LF line endings so Prettier checks and generated bindings match on Windows. CI runs frontend lint/format/type checks once on Linux, and Rust fmt/clippy/tests plus the app build on both Ubuntu 22.04 and Windows.
- 2026-09-27: PROPOSAL (needs owner decision before FTS writes land in M2/M4): §5's `articles_fts` is contentless (`content=''`), so rows can't be deleted without their original text, and `ON DELETE CASCADE` from feeds bypasses Rust entirely. Proposed fix: add `contentless_delete=1` (SQLite ≥ 3.43, bundled) and an `AFTER DELETE ON articles` trigger that deletes the matching FTS row. M1 creates the table exactly as specified.
- 2026-09-27: Every merge to main publishes a GitHub Release with Linux (`.AppImage`, `.deb`, `.rpm`, built on Ubuntu 22.04) and Windows (NSIS `-setup.exe`, `.msi`) installers, once CI passes on that commit (`.github/workflows/release.yml`) (owner decision; replaces §13's "build bundles on tags"). Pull requests that change packaging run the same builds without publishing.
- 2026-09-27: Release version = `<major>.<minor>` from `src-tauri/tauri.conf.json` + `.<patch>` (e.g. `0.1.7`, tag `v0.1.7`); the repo's patch digit is ignored. To start 0.2, bump the version in `tauri.conf.json`, `Cargo.toml` and `package.json` (owner chose numbered per-merge builds; purely numeric versions because RPM forbids `-` in versions, and deb/rpm would sort `0.1.0-N` after `0.1.0`, unlike semver; always increasing because main can't be force-pushed). How `<patch>` is computed changed on 2026-09-27; see the marker-tag entry below.
- 2026-09-27: Windows installers are not code-signed until a certificate exists (SmartScreen warns on first run). Updater signing stays in M8.
- 2026-09-27: Windows installers embed the WebView2 bootstrapper (§2: "WebView2 bootstrapper included").
- 2026-09-27: On MSVC targets, the Common Controls v6 manifest is embedded through the linker (`/MANIFEST:EMBED`) instead of by tauri-build (which only covers binaries), so `cargo test` executables start on Windows instead of failing with `STATUS_ENTRYPOINT_NOT_FOUND`.
- 2026-09-27: FLAG for M8 (spec conflict): the AppImage is about 100 MB because it bundles WebKitGTK, far above §12's "< 25 MB AppImage" target; the `.deb`/`.rpm` are about 5 MB. The target likely needs revising, or the AppImage dropping, when packaging is finalised.
- 2026-09-27: Pull requests that only change documentation (Markdown files anywhere, `docs/`, `LICENSE`) skip CI's slow app jobs (Rust fmt/clippy/tests and app builds on Linux and Windows); the frontend job still runs. The skip is done at job level, so skipped jobs report "skipped" and would still satisfy required checks. Pushes to main always run everything, because they gate releases and fill the build caches (owner request).
- 2026-09-27: The display name is **Omarss**: product name, window title, UI, installer and release names, publisher, and docs. This matches the other oma apps (Omacalc, Omacut, Omawrite), which use a Title-case `Name=` and lowercase technical names. Technical identifiers therefore stay lowercase `omarss`: binary, desktop file, icon, window class, deb/rpm package, npm package (npm requires lowercase), Cargo crate, identifier `dev.omarss.app`, data/config folders (existing installs keep their data), `omarss-img://`, `.omarssbackup`, keyring key, and the repo name (owner request).
- 2026-09-27: The Windows MSI upgrade code is pinned to `586b92e7-c31b-5a7b-8797-17cbcbb6f245`, the value Tauri derived from the old product name "omarss". Tauri derives the code from `productName` case-sensitively, so without the pin, installs from v0.1.5 and earlier would sit alongside new ones instead of upgrading.
- 2026-09-27: The Linux desktop file is named `Omarss.desktop`. Tauri 2 always names it after `productName`, and this cannot be configured, so it differs from the siblings' lowercase file names. It still sets `Exec`, `Icon` and `StartupWMClass` to `omarss`, and the window class is `omarss`, so desktops still match windows to the launcher entry.
- 2026-09-27: HTTP uses reqwest 0.13 with rustls on the `ring` crypto provider (`rustls-no-provider` plus an explicit provider) and the OS certificate store (rustls-platform-verifier). The default provider, aws-lc-rs, needs CMake/NASM to build on Windows.
- 2026-09-27: Redirects are followed by hand (at most 5). The stored feed URL follows 301/308 hops until the first 302/307 in the chain (§7.1).
- 2026-09-27: Feed encoding precedence is byte-order mark, then HTTP `charset`, then XML prolog, then UTF-8 with replacement characters (§7.3 lists the sources but not the order; this is the XML/RFC 7303 order).
- 2026-09-27: Malformed XML gets one repair-and-retry pass: stray `&` escaped, HTML named entities turned into numeric references, a missing `<rss version>` added. CDATA is left untouched (§7.3).
- 2026-09-27: Dates use our own lenient parser (feed-rs's isn't public): RFC 3339, RFC 2822 with common fixes (full or odd month names, wrong weekdays, `UTC`), and ISO dates without a zone or time, taken as UTC. Dates more than a day in the future count as missing, i.e. first-seen time.
- 2026-09-27: Items without a title get an 80-character excerpt of their text as the title ("Untitled" if there's no text). Media RSS descriptions are used when an item has no summary or content (video channels).
- 2026-09-27: M2 removes all iframes when sanitising. The YouTube/Vimeo embed allowlist (click-to-load, `youtube-nocookie.com`) comes with M3's sanitisation hardening (§8.2).
- 2026-09-27: Remote images stay blocked by the CSP until M3's image proxy (§8.4); the reader hides blocked images. Tracking-pixel removal, `utm_*` stripping and list thumbnails also wait for M3 (thumbnails need the proxy, and no thumbnail column exists yet).
- 2026-09-27: PROPOSAL: §7.1's per-feed User-Agent override needs a column the §5 schema doesn't have. It's deferred to the feed-settings work in M3, which would add it in a migration.
- 2026-09-27: Refresh interval: global setting `refreshIntervalMinutes` (30; 0 = manual only); per-feed override in `feeds.fetch_interval` seconds (NULL = global, 0 = manual only). The Edit feed dialog offers §6.5's options.
- 2026-09-27: Offline detection without an OS API: if every feed in a refresh run fails to connect, across at least two hosts, the machine is treated as offline. Those failures don't count as feed errors, and the feeds retry every 60 s until something connects. A single host failing is an ordinary feed error (§7.2).
- 2026-09-27: The metered-connection pause (§7.2, Windows-only and opt-in) is not in M2; it needs the settings UI (M3).
- 2026-09-27: Favicons are served to the WebView by the `omarss-img://` protocol at `icon/<file>`. Files are named `<feed id>-<unix time>.png`, so a new icon gets a new URL and the weekly re-fetch needs no schema column. A failed fetch is retried at most once a day per app session (§7.5).
- 2026-09-27: "Deleted feeds" is a paused feed row with the sentinel URL `omarss:deleted-feeds`. Kept articles' GUIDs are prefixed with their old feed id so they stay unique. It only appears when it has articles (§6.1).
- 2026-09-27: M2 marks articles read on open only. The "after N seconds" and "on scroll past" options (§6.2) come with the settings UI in M3.
- 2026-09-27: The article list uses keyset pagination on `(published_at, id)` in pages of 100, with fixed 100 px rows rendered by a virtual list. Migration 0002 adds two partial indexes for list order and per-feed unread counts (§6.2, §12).
- 2026-09-27: New articles arriving during a refresh don't reshuffle a list being read: a "Show new articles" button appears instead. An empty list reloads by itself.
- 2026-09-27: Nothing is written to the full-text index until search lands in M4, which will backfill it (and settle the `contentless_delete` proposal above).
- 2026-09-27: Folder names are unique per account ignoring case, to avoid confusing near-duplicates.
- 2026-09-27: Sidebar reordering uses HTML5 drag and drop (verified with synthetic drag events). Keyboard and assistive-tech users can move feeds with the Edit feed dialog's Folder field.
- 2026-09-27: The parsing fixtures (§13: at least 30 real-world feeds, including broken ones) are synthetic replicas of real publishers' formats and quirks, so the public repo holds no third-party content.
- 2026-09-27: Version bumped to 0.2.0 for M2, so releases are numbered `0.2.<commits on main>`, matching M1's 0.1.0 changelog entry.
- 2026-09-27: The Claude review workflow gets read-only tools (Read, Grep, Glob, and read-only `gh`/`git` commands) plus instructions to review large PRs file by file and skip generated files. A single `gh pr diff` of a milestone PR (10k+ lines) was truncated, and the review quit without commenting. Draft and fork PRs are skipped, git credentials are not persisted in the checkout, a newer push cancels a running review, and a final step warns when no review was posted, since the job succeeds either way (owner request).
- 2026-09-27: When a known article's content hash is unchanged but its link, author, `updated_at` or enclosures differ, only those are rewritten. It doesn't count as an update, so it never marks the article unread or shows "Show new articles". The content hash stays title + summary + content, so upgrading doesn't flag the whole library as updated (§7.4).
- 2026-09-27: `published_at` is set when an article is first stored and never refreshed. Articles without a date get their first-seen time, which would otherwise move on every fetch, and a changing date would reshuffle the list and its keyset pagination (§6.2, §7.4).
- 2026-09-27: Discovery still accepts `<link rel="alternate">` of plain `application/json` (JSON Feed 1.0's advertised type), but fetches it and keeps it only if it parses as a feed. Every WordPress page links its REST API (`/wp-json/...`) with that type, and offering it as a feed would be wrong; dropping the type would lose older JSON Feeds (§6.1).
- 2026-09-27: Favicon sources are decoded with limits: at most 1024 px a side and 32 MiB of allocation. Larger images are treated as no icon, and the next source is tried (§7.5).
- 2026-09-27: Release patch numbers reset per minor version instead of counting every commit on main: a lightweight marker tag `v<major>.<minor>` (e.g. `v0.2`) is pushed at the commit that bumps `tauri.conf.json`'s version, and the release workflow counts commits since that tag instead of `git rev-list --count HEAD`. Falls back to the old whole-history count (with a warning) if the marker tag is missing, so a forgotten tag doesn't break releases. When starting a new minor version, push the marker tag alongside the version bump: `git tag v<major>.<minor> <bump commit> && git push origin v<major>.<minor>` (owner request; `v0.2` tagged retroactively at `2c86afe`, the M2 commit that set version 0.2.0).
- 2026-09-27: Migration 0003 adds `feeds.user_agent` (per-feed User-Agent override, settling the M2 proposal; §7.1 "advanced") and `articles.thumbnail_url` (list thumbnails, §6.2/§7.3). The thumbnail is the Media RSS thumbnail, else an image `media:content`, else the content's first http(s) image that isn't declared smaller than 48 px.
- 2026-09-27: Settings are validated when saved: values the UI never offers (e.g. a 7-minute interval, a 300 % scale, a bad proxy URL) are rejected with a message. A stored out-of-range value falls back to its default, field by field, like an unparsable one. Internal state kept in the `settings` table uses keys prefixed `state.` (e.g. `state.lastVacuumAt`), which the `Settings` object ignores.
- 2026-09-27: Shortcuts `t` (add tag), `f` (full text) and `/` (search) are not bound until their features exist (M4/M5); they'll be added to the same action table. Bindings are stored as overrides only (`shortcuts`: action → keys), so new defaults reach existing users. Rebinding replaces all of an action's keys, rejects keys another action uses (including a single key that would shadow another action's two-key sequence), and "Reset" restores the default. `Enter` and `Space` keep their normal meaning on a focused button, link or control, except on article rows, where `Space` scrolls the reader (§6.7).
- 2026-09-27: "Mark all as read" applies to unread articles in the current view (optionally published more than a day or a week ago). Undo is held in memory by the backend for the latest batch only, as a token, so large batches don't cross IPC twice. Undo is offered for 10 s (§6.2).
- 2026-09-27: OPML import adds all new subscriptions in one transaction and makes them due at once, so the scheduler fetches them with the normal `refresh:progress` reporting. There is no separate `import:progress` event, since inserting rows takes milliseconds even for 300 feeds (§6.4). Only folders that contain feeds are created, and existing folders are matched ignoring case. An outline whose `text` differs from its `title` keeps `text` as the custom title. Export writes the displayed title as `text` and the feed's own as `title`, so custom titles round-trip. The Local account is the only account, so "export a single account" isn't offered yet (M7).
- 2026-09-27: The OPML file pickers are opened from Rust (`tauri-plugin-dialog`), so the WebView gets no dialog or file-system permissions (§11.4). The plugin uses its xdg-desktop-portal backend (with rfd's zenity fallback), not the default in-process GTK dialog: from a Tauri app under Wayland (verified on Hyprland) the GTK dialog never appeared, while the portal dialog does. Windows uses the native dialog either way.
- 2026-09-27: The full `.omarssbackup` export/import (§6.4) stays in M8, which lists backup/restore in §14.
- 2026-09-27: Retention (§6.9) runs two minutes after start-up and then daily, and also after each refresh batch that brought new articles. "Tagged" means the article has an `article_tags` row. The weekly `VACUUM` runs when no refresh is in progress; its clock starts on first run, so a fresh install isn't vacuumed at once. "Compact database" runs the retention cleanup and then `VACUUM`.
- 2026-09-27: Image proxy (§8.4) URLs are `omarss-img://localhost/img/<base64url(image URL)>` (`http://omarss-img.localhost/…` on Windows). Cache files are named by the SHA-256 of the URL and start with a content-type line. Only `image/*` responses (or bytes that sniff as an image) up to 16 MB are cached, known trackers are refused, a failed URL isn't retried for 10 minutes, and at most 6 downloads run at once. LRU uses file modification times, which reads refresh, and eviction frees down to 90 % of the limit. Sizes use decimal megabytes, like every size the UI shows.
- 2026-09-27: "Load remote images" (§8.4) options: **Always** (reader and list thumbnails), **Only in articles I open** (reader only; this is how §8.4's "Only for starred & opened" is read, since starred articles are opened to be read too; no prefetching of starred articles' images), and **Never** (the reader offers "Load images"). Images and `utm_*` stripping are applied when an article is displayed, not stored, so changing either setting also applies to old articles. Stripping covers the article's own link and links in its content.
- 2026-09-27: YouTube/Vimeo iframes are stored as `<figure class="omarss-embed" data-embed="…">` placeholders with a link to the video page. The reader adds a "Play video" button, which inserts a sandboxed `youtube-nocookie.com` / `player.vimeo.com` iframe (§8.2). WebKitGTK routes iframe navigations through the app's navigation guard, so video hosts (YouTube, Google, Vimeo) are let through instead of being opened in the browser.
- 2026-09-27: FLAG: on Linux the app's origin is `tauri://localhost`, which sends no `Referer`, and YouTube now refuses to play without one ("Video player configuration error", error 153). The link to the video page stays under the player as a fallback. Windows (`http://tauri.localhost`) should be unaffected. A real fix would need a web origin for the embed (e.g. a small http page served by the app), so it's left for the owner to decide.
- 2026-09-27: Tracking pixels (§8.4) are images declared 1×1 or smaller, or served from a built-in list of tracker hosts and paths (in `content/rewrite.rs`). They are removed at ingest, and again at display for articles stored before M3.
- 2026-09-27: A feed counts as broken (§6.1) with 3+ consecutive errors, or when it's paused with an error (a `410 Gone` pauses a feed at its first error). "Broken feeds" is a page shown in place of the list and reader, not an article `View`. It appears in the sidebar only when a feed is broken. Editing a feed's address resets its validators and errors and fetches it again.
- 2026-09-27: Interface scale (§6.8) uses the WebView's native zoom (`set_zoom`), so layout reflows like browser zoom. Sidebar and list widths are settings (`sidebarWidth`, `listWidth`), saved when a drag ends. The splitters also move with the arrow keys. Window size/position stays with the window-state plugin in M6.
- 2026-09-27: The accent colour (§6.8) overrides `--accent`, `--accent-text`, `--focus-ring` and `--accent-contrast` (black or white, whichever contrasts more), and tints `--bg-selected` with `color-mix`. `custom.css` is read from `<config>/omarss/custom.css` (at most 512 KB) at start-up and by "Reload custom CSS", and is added after the app's styles.
- 2026-09-27: A manual proxy (`http://`, `https://`, `socks5://`, `socks5h://`) takes effect immediately: all clones of the HTTP client share one `reqwest::Client`, which is rebuilt when the setting changes. An empty value uses the system proxy (§7.1).
- 2026-09-27: "Pause on metered connections" (§7.2) is Windows-only: WinRT `NetworkInformation` counts a connection as metered when its cost is Fixed or Variable, when roaming, or when over its data limit. While metered, automatic refresh waits and re-checks every 5 minutes; manual refresh still runs. The option is hidden on Linux (the spec's NetworkManager support is a MAY).
- 2026-09-27: Mark-as-read modes (§6.2): **on open** (default), **after N seconds open** (1–60, default 3; leaving sooner leaves it unread), and **on scroll**, where rows that scroll entirely above the list are marked in batches, and opening an article still marks it read.
- 2026-09-27: The two-pane layout (§6.2) shows the list, and opening an article replaces it with the reader, which has a Back button; `Esc` returns to the list.
- 2026-09-27: Settings has General, Reading, Refresh, Appearance, Keyboard, Privacy & network, Storage and About. Notifications, Accounts and Rules (§11.2) are added with M6, M7 and M5, which bring their settings.
- 2026-09-27: The reader's Share menu (§6.2) copies with the Clipboard API and falls back to `execCommand("copy")`, which WebKitGTK may need. "Email link" opens a `mailto:` link.
- 2026-09-27: Version bumped to 0.3.0 for M3.
- 2026-09-27: From 0.3 on, release patch numbers need no marker tag. The patch number counts main's first-parent commits (one per merged PR) since the version in `tauri.conf.json` became `<major>.<minor>`, so the merge that bumps the version is released as `<major>.<minor>.0` whether PRs are merged, squashed or rebased (the marker tag had to be an ancestor of main and made the bump merge `.1`). `v0.2` stays as a legacy marker so 0.2 numbers never go backwards. Don't create `v0.3`-style marker tags; they'd switch that version back to the old count (owner request: M3 should release as v0.3.0). Supersedes the "push the marker tag" step above.
